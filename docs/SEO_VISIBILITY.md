# WAY Esports: обновление SEO и дальнейшая видимость

Канонический домен: **https://wayesports.space**. Изменения подготовлены в проекте; сборка локально не означает публикацию на сервере или индексацию поисковиками.

## Что изменено

- `/sitemap.xml` теперь направляется в API через production reverse proxy. Карты разделов доступны по `/sitemaps/*.xml`, карта публичных скаутских профилей — `/sitemap-player-promotion.xml`. Их ссылки используют публичный домен, а не Host запроса или список CORS.
- JSON-LD в HTML для роботов сериализуется как JSON, без превращения кавычек в HTML entities. Сохранено безопасное экранирование содержимого script. Организация и сайт связаны постоянными `@id`; неподтверждённые аккаунты соцсетей удалены из `sameAs`.
- Поисковые и социальные роботы получают HTML публичных страниц. Добавлены OAI-SearchBot, ChatGPT-User, PerplexityBot, Perplexity-User, Claude-SearchBot и Claude-User. Для ответов, зависящих от User-Agent, установлен `Vary: User-Agent`.
- В снимках новостей доступны полный текст, автор, дата и разметка NewsArticle; в турнирах — описание и правила. Черновики не выдаются, фильтры приватных команд и заблокированных пользователей сохранены. Отсутствующие страницы в SEO-renderer возвращают 404, ошибки сервиса не кэшируются.
- Добавлены полноценные статические страницы `/about/` и `/ru/about/`, работающие без JavaScript: описание платформы, ссылки на семь игр и ответы о регистрации. Языковые альтернативы указаны только для этих двух реально переведённых страниц.
- Главная содержит начальный HTML с описанием платформы и обычными ссылками. Добавлены ссылки на About и RSS в интерфейсе. `/feed.xml` содержит до 30 опубликованных новостей.
- Исправлены canonical и метаданные соцсетей, `www` и старые одиночные маршруты перенаправляются на основные URL. Закрытым разделам добавлен `X-Robots-Tag: noindex`; robots.txt сохраняет доступ к изображениям из `/api/uploads/`.
- Карты основных разделов не получают фиктивную дату обновления при каждом запросе.

## Установка на сервере

Инструкция относится к `docker-compose.yml` в корне этого проекта: сервисы `api`, `web`, `reverse-proxy`, конфигурация `nginx/reverse-proxy.conf`. Системный `nginx.service` в этой схеме не используется.

Загрузи `way-seo-update.zip` в каталог проекта на сервере (например, `~/way-esports`). Архив содержит изменённые исходники, проверки и эту инструкцию. `.env`, базы данных, сертификаты, uploads и node_modules в него не входят.

В каталоге проекта:

```bash
unzip -o way-seo-update.zip &&
docker compose build api web &&
docker compose run --rm --no-deps reverse-proxy nginx -t &&
docker compose up -d --no-deps api web &&
docker compose up -d --no-deps --force-recreate reverse-proxy
```

Убедись, что уже заданные `PUBLIC_WEB_URL` или `APP_URL`, если они есть в серверном `.env`, равны `https://wayesports.space`. Если обе переменные отсутствуют, код использует этот домен по умолчанию.

Проверь `docker compose ps`: `api` и `web` должны стать healthy. Отдельный `docker compose run` проверяет текущую конфигурацию с диска до применения. Пересоздание только proxy обновляет Docker bind mount даже при замене файла через git/редактор с новым inode; оно вызовет короткий перерыв в обслуживании сайта.

После запуска:

```bash
curl -fsS https://wayesports.space/sitemap.xml
curl -fsS https://wayesports.space/sitemaps/core.xml
curl -fsS https://wayesports.space/feed.xml
curl -fsSI https://wayesports.space/about/
curl -fsSI https://wayesports.space/ru/about/
curl -fsS -A 'OAI-SearchBot' https://wayesports.space/
curl -sS -o /dev/null -w '%{http_code}\n' -A 'Googlebot' https://wayesports.space/news/not-an-id
```

Первые ответы должны быть XML, About — HTTP 200, ответ OAI-SearchBot должен содержать описание платформы и JSON-LD, последний запрос — HTTP 404. Проверь также конкретную опубликованную новость с Googlebot и Twitterbot: заголовок, полный текст, canonical и изображение должны соответствовать статье. `/about` должен перенаправляться на `/about/` без перехода на HTTP.

Если используется CDN, сбрось кэш HTML, robots.txt и sitemap после установки. Кэш должен учитывать User-Agent или обходить кэширование HTML со стороны reverse proxy; нельзя раздавать снимок робота обычным посетителям. Карточки ссылок в соцсетях могут сохранять старый превью-кэш: используй инструменты повторного обхода конкретной платформы.

## Проверки в проекте

```bash
cd backend
npm run build
npm run test:seo
cd ../way-esports-front/frontend
npm run type-check
npm run build
node scripts/check-public-pages.mjs
```

SEO-тесты проверяют реальные HTTP-ответы Express на тестовых данных: JSON-LD, полный текст, canonical, sitemap/RSS, 404 и ограничения публикации. Они не требуют MongoDB. Проверка статических страниц выполняется после frontend build. Проверка production nginx и подключения к живой БД выполняется на сервере; локальные тесты не заменяют её.

## Что сделать владельцу после публикации

1. Подтвердить домен в [Google Search Console](https://search.google.com/search-console) и [Bing Webmaster Tools](https://www.bing.com/webmasters/). Добавить `https://wayesports.space/sitemap.xml`, проверить главную и About через инспекцию URL. Это не выполнено автоматически: нужны аккаунты владельца и доступ к подтверждению домена.
2. Указать сайт в настоящих официальных профилях организации. Добавлять `sameAs` только после подтверждения точных URL Telegram, Discord, YouTube, Twitch и других принадлежащих WAY Esports страниц. Не использовать предполагаемые адреса.
3. Публиковать содержательные страницы реальных событий: игра, формат, даты и часовой пояс, правила, условия входа, результаты и автор материала. Для новостей — собственный текст и источники. Поддерживать актуальность завершённых турниров.
4. Развивать английские материалы для международной аудитории и отдельные качественные переводы. Не размечать непереведённые страницы как десятки языковых версий.
5. Получать реальные упоминания и ссылки от организаторов, команд и участников через сотрудничество. Самостоятельно размещать анонсы в принадлежащих проекту каналах со ссылкой на конкретное событие. Массовая генерация однотипных страниц и покупка ссылок не входят в эту работу.
6. По Search Console отслеживать индексирование, показы, запросы и переходы, по аналитике — переходы на события и регистрации. Улучшать страницы по этим данным, а не по числу добавленных метатегов.

## Поиск и ИИ: ограничения

Доступный HTML, достоверные факты, обычные ссылки, корректный robots.txt и карты сайта помогают обнаружению и пониманию страниц. Они не гарантируют ранжирование, попадание в ответы ИИ или конкретный срок индексации. Для Google AI-функций действуют обычные требования SEO; особый `llms.txt` или специальная AI-разметка не обязательны. Разрешение поискового обхода OpenAI и разрешение обучения GPTBot — разные настройки; это обновление не добавляет отдельного разрешения на обучение.

Существующий динамический renderer для распознаваемых роботов улучшен, но это всё ещё промежуточная архитектура. Полноценный серверный рендеринг всех публичных динамических страниц остаётся отдельной задачей: сейчас статические About доступны одинаково всем, а остальные страницы приложения используют React и снимки для известных роботов. У обычного SPA-запроса на отсутствующий динамический URL статус может оставаться 200; корректный 404 в этом обновлении обеспечен SEO-renderer.
